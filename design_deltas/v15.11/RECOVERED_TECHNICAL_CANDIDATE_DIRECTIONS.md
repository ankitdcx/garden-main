# Garden v15.11 — Recovered Technical Candidate Directions

**Status:** NONCANONICAL RETENTION. This file preserves technical content recovered from the September 20 pending-candidate ledger and subsequent project discussions for candidate directions that did not have a separately recoverable full specification. It does not fill missing fields by invention.

## Global admission procedure

Every candidate must:
1. recover exact source/problem/intent;
2. compare against the current owner graph and stronger/duplicate mechanisms;
3. compare DO_NOTHING and simpler alternatives;
4. identify minimal owners;
5. add/reuse schemas, contracts, invariants and tests only where warranted;
6. perform applicable rights/privacy/authority/safety/security/law review;
7. close dependencies/references;
8. obtain independent falsification/review;
9. propagate admitted changes through affected owners/tests/registries/docs;
10. re-audit globally;
11. escalate constitutional/original-intent/major-architecture decisions to the applicable human authority boundary;
12. preserve specification != proof != implementation != empirical validation != certification.

## V1511-TRN-001 — Transition Fabric staged migration

Upgrade existing transition/GTF machinery rather than create a second transition engine.

Required design questions:
- staged migration from current AI governance/institutions to Garden;
- dual-run/shadow/parallel validation before authority transfer;
- explicit authority-migration rules;
- independent verification of transition decisions;
- rollback/fail-safe criteria;
- compatibility with existing law, institutions, infrastructure and deployed AI;
- capture/corruption resistance during transition;
- measurable entry/exit criteria per stage;
- transition-specific human-authority/HITL boundary;
- evidence threshold for recommendation -> shared control -> transferred control;
- post-transfer monitoring and authority restoration/revocation.

## V1511-AUTH-001 — Authority provenance/scope/delegation/revocation

Every consequential permission should trace:
- legitimate source;
- exact scope;
- purpose, recipient and action class;
- delegation chain;
- expiry/freshness;
- revocation path;
- invalidators;
- enforcement point;
- current authority ceiling.

Compare against existing authority provenance, shared-state authority composition, Access, Policy, Law, Human Sovereignty, AAP and FunctionContract machinery before adding schemas.

Candidate principle: permission to pursue a goal != permission to use any means. Method/means authorization is independently checked when it crosses a distinct rights/privacy/safety/security/legal/human-effect boundary.

## V1511-EVO-001 — AI-led proactive Garden upgrade closure

Formalize:
`find -> investigate -> compare -> attack/falsify -> verify -> patch -> propagate -> re-audit -> close/escalate`.

Requirements:
- source-bound issue discovery;
- whole-system impact closure;
- independent adversarial review;
- machine-executable finding lifecycle;
- patch propagation across affected owners/tests/registries/docs;
- post-fix global re-audit;
- states OPEN/CONFIRMED/PATCHED/RECHECKED/CLOSED/DEFERRED/BLOCKED;
- no closure by prose confidence or majority vote alone;
- proactive gap discovery rather than waiting for a human to identify each issue.
