# Tree Core v0.8.1 — Reading Guide

**Source:** [TREE_CORE_v0.8.1_2026-09-23.txt](TREE_CORE_v0.8.1_2026-09-23.txt). This guide is noncontrolling and does not replace the full source.

The Tree Core is a **structural integration candidate**, not a new canonical release, completed atomic owner register or group-review PASS.

It organizes the design into **Root** (constitutional boundaries), **Substrate** (typed meaning and sources), **Trunk** (shared controls, knowledge and checks), and **Boundary** (contracts for theories, tools, institutions and implementations). A cross-cutting **Register** preserves exact source-to-owner mappings and historic dispositions; a **Release Gate** requires two-way retention and independent review.

Each semantic assertion needs a versioned, scoped controlling owner. The register must preserve source identity/span/hash, qualified statuses, applicability, dependencies and historical disposition. Merging duplicates is permitted only with recorded equivalence or governed disposition; UNKNOWN and conflicts cannot be silently discarded.

The tree is a navigation structure, not the whole architecture. It also projects effect/control, P0–P11 lifecycle, capability/dependency and historical views. These views cannot create authority. Retain rights, consent, privacy, safety and Human-Effect limits throughout migration.

**Not yet established:** a complete atomic register, lossless reconstruction, formal equivalence, implementation or canonical admission.
