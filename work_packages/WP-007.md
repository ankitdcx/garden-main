# WP-007 — Integrator audit and admission hardening

Status: IN_PROGRESS

## Objective

Make the Garden integration/admission layer independently auditable before scaling the external swarm.

## Required controls

1. Every substantive finding disposition produces an `IntegrationDecisionReceipt/v1` with a stable finding ID and decision ID.
2. Canonical absence/coverage claims carry a deterministic search trace over all five current canonical files, including source hashes and matching lines.
3. HIGH/CRITICAL findings and substantive semantic design deltas require a same-question reproduction attempt from a different model family when an admissible zero-cost route exists.
4. Substantive design deltas include an explicit DO_NOTHING comparison.
5. Challenger review audits integrator accept/reject decisions and records disagreements without silently overriding them.
6. Findings remain traceable from model handoff through decision, test/commit or design-delta outcome, and ledger entry.
7. WP-006 successor materialization uses an admitted per-file delta manifest and a mechanical drift check so the generated candidate equals the predecessor plus exactly the expected admitted diffs.

## Initial implementation

- `reviews/integration/decision.schema.json`
- `reviews/integration/README.md`
- `scripts/search_canonical.py`
- `scripts/validate_integration_receipts.py`
- `scripts/check_successor_drift.py`

## Completion boundary

WP-007 is not complete merely because the files exist. It completes only after repository CI exercises the gates, the hourly integrator emits real decision receipts/ledger entries, and the challenger demonstrates that it can independently audit those decisions.
