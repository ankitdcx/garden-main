# WP-009 — Repo-wide GSL conformance and Garden capability closure

Status: OPEN — BASELINE AUDIT / PROFILE IMPLEMENTATION

## Objective

Treat every material artifact and change in `garden-main` and `garden-swarm` as a typed Garden/GSL artifact or action, with explicit applicability of Garden mechanisms rather than informal prose-level compliance.

This work package does **not** claim that the current repositories are fully GSL v45.1 compliant or Garden-certified. It creates the machinery required to make that claim testable and progressively close the frontier.

## Governing principle

`Garden mechanism exists in source` != `repository artifact is bound to it` != `runtime enforces it` != `evidence proves conformance`.

For each material artifact/change, the applicable subset of Garden must be explicit. Irrelevant modules are not invoked decoratively; applicable modules may not be silently skipped.

## Current audit finding

The repositories contain strong isolated implementations of DesignEpoch freshness, bounded authority, ActionGate, verifier receipts, source binding, signed delegation, bounded leases, swarm provenance and evolution typing. The main remaining gap is **composition**: these mechanisms are not yet joined into one repo-wide GSL conformance path, and several canonical capabilities (Compare/Reason/Proof separation, FunctionContract coverage, AAP assurance selection, registered algebra semantics, durable audit receipts) are only partially executable.

## Correctness sequence

### WP-009A — Whole-repo GSL load/profile

1. Classify every repository file into a declared artifact class.
2. Bind the classification profile to the current canonical source root / DesignEpoch.
3. Declare required and conditional Garden modules for changes affecting each artifact class.
4. Preserve an explicit `FRONTIER` class instead of falsely claiming semantic coverage.
5. Produce a deterministic machine-readable inventory and coverage report.

### WP-009B — Production evolution transport

Complete WP-008 so real hourly actions emit machine-checkable typed action + DesignEpoch + source-obligation + trusted authority + ActionGate receipts. No event may supply/mint its own trusted authority.

### WP-009C — FunctionContract closure

Every executable repository function that can affect Garden state, evidence, authority, admission, orchestration or canonical materialization receives a generated/declared FunctionContract binding, including input/output/error/UNKNOWN/effect semantics and applicable proof/test obligations.

### WP-009D — Compare / Reason / Proof / Evidence separation

Add typed receipts so:

- Compare records predecessor/DO_NOTHING/alternatives and bidirectional gaps.
- Reason records strategy/tier, assumptions, uncertainty, counterexamples and dependencies.
- Proof records explicit proof obligations and verifier class/results.
- Evidence remains evidence and cannot by itself mint proof or authorization.
- Authorization remains an ActionGate/authority result, not a reasoning/proof result.

### WP-009E — Algebra conformance

Implement only the canonical algebra instances actually used by the pipeline: Process, Policy, Decision, Conformance, Evidence and Bridge. Operators must bind to registered signatures/laws/non-laws; undeclared associativity, commutativity, idempotence, distributivity or ordering must never be assumed.

### WP-009F — AAP / assurance selection

Replace fixed assurance conventions with a typed AAP selection receipt that chooses the smallest sufficient Garden subset and assurance depth from action impact, novelty/uncertainty, evidence/proof needs, freshness, rights/authority/safety/security consequences and resource budget.

### WP-009G — Durable audit and compliance

Gate/verification/compare/reason/proof receipts become durable and tamper-evident (content hashes plus append-only linkage or equivalent protected persistence). In-memory logs are test fixtures only.

### WP-009H — Duplicate-semantics convergence

Converge overlapping public prototype, private evolution kernel and SCEP bootstrap implementations through shared schemas and conformance vectors. Public/private implementations may differ, but the same canonical semantic vectors must produce compatible results.

### WP-009I — Source obligation closure

Expand the current conservative extractor beyond definitions/schemas/normative prose to cover the canonical structured classes needed for implementation: FunctionContracts, invariants, tests, registries, AlgebraSignatures, profiles, engine/owner bindings and reference-closure identifiers. Coverage must remain explicitly partial until every material source class is classified.

### WP-009J — Repo-wide CI gate

Add a top-level GSL conformance workflow for all material changes. A change must carry the applicable source obligation / DesignEpoch / module bindings and may not bypass WP-007/WP-008 governance. Canonical predecessor files remain immutable; successor materialization follows WP-006.

## Relevant Garden capabilities

Always or commonly applicable:

- GSL type/effect/scope semantics
- DesignEpoch and dependency closure
- source obligations and provenance
- FunctionContracts
- ActionGate and authority/delegation
- AAP / assurance reuse and escalation
- Compare / Reason / Proof / Evidence separation
- Process, Policy, Decision, Conformance, Evidence and Bridge algebras where their operands/operators are actually used
- Audit / Compliance / correction and invalidation
- Human sovereignty / constitutional veto and canonical-promotion boundary
- Security and privacy boundaries for external agents/providers

Conditionally relevant analytical/theory profiles:

- GCL for prioritizing high-leverage interventions, never as an authority source
- CDDT for bounded cross-domain discovery, not admission by analogy
- AGI hardening / novelty / multi-agent coordination for swarm operation
- physical/control theories only when the repository action has corresponding physical/embodied semantics
- CASI remains deferred in the current v15.5 source and must not be silently activated

## Non-goals

- Do not call classification itself certification.
- Do not invoke every Garden module for every trivial file.
- Do not auto-promote canon.
- Do not let a model's agreement substitute for proof, evidence or authorization.
- Do not duplicate canonical semantics in another ad-hoc gate when an existing Garden mechanism can own them.

## Completion criterion

WP-009 is complete only when a deterministic repo audit can trace every material change:

`source obligation -> typed GSL action/artifact -> DesignEpoch/dependencies -> applicable Compare/Reason/Proof/Evidence -> authority/AAP/policy -> ActionGate -> Process transition -> verifier/conformance receipt -> durable audit -> resulting artifact/effect`

and can identify any missing link as an explicit, machine-checkable frontier rather than silently treating it as compliant.
